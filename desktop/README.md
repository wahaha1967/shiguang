# Shiguang Study Room · Windows Desktop

A single-file Windows desktop build of 拾光自习室. The UI is the unchanged
`web/index.html` from the Python release; the whole backend is rewritten in Go
and embedded into one `.exe`. No Python, uv, venv, or Node runtime is needed to
run it.

- Platform: Windows 10/11 x64
- GUI: Wails v3.1.0 + Microsoft Edge WebView2
- Storage: SQLite through `modernc.org/sqlite` (pure Go, `CGO_ENABLED=0`)
- HTTP: standard library only, loopback interface only

## Requirements

To **run**: Windows 10/11 x64 and the WebView2 runtime (bundled with Windows 11;
most Windows 10 machines already have it).

To **build**:

- Go 1.26+, with `CGO_ENABLED=0`
- Wails v3.1.0 CLI (`wails3`) on `PATH`

## Build and test

```bash
wails3 task test              # go test ./...
wails3 task vet               # go vet ./...
wails3 task windows:build     # build/bin/shiguang-study.exe
wails3 task package           # dist/拾光自习室/… plus a windows-x64 zip
```

`windows:build` generates the manifest/version `.syso` first, then builds with
`-H windowsgui` so no console window appears. The task runs the test suite as a
dependency.

To run from source:

```bash
wails3 task serve             # HTTP only on 127.0.0.1:4312
go run ./cmd/study            # desktop window, random loopback port
```

Command-line flags:

| Flag | Meaning |
|---|---|
| `--serve` | Start only the loopback HTTP service (debugging) |
| `--port N` | Fixed port; `0` (default) picks a free one |
| `--open` | With `--serve`, open the app in the default browser |

## Data and compatibility

The desktop build uses the same data directory, schema, token, owner key, and
encryption format as the Python backend:

```
%USERPROFILE%\.local\share\shiguang-study\
├── study.db      # SQLite database (11 tables, same schema)
├── token         # generated once, 32 random bytes, base64url
└── .env          # SHIGUANG_SECRET used to encrypt provider keys
```

An existing Python `study.db` opens directly. The legacy
`ai_config.transport` column is dropped on first open, exactly as before.
Provider keys use the same AES-256-GCM format, so they keep working as long as
the same `SHIGUANG_SECRET` is used. Python searched for `.env` from the working
directory; the desktop build reads the data directory and the executable
directory. A `.env` next to the executable is treated as untrusted and may only
supply `SHIGUANG_SECRET`; other keys there are ignored. If the old `.env` lives
elsewhere (for example in the source tree), point `SHIGUANG_ENV_FILE` at it or
copy it into the data directory.

Overrides: `SHIGUANG_DATA_DIR`, `SHIGUANG_DB`, `SHIGUANG_TOKEN`,
`SHIGUANG_ENV_FILE`, `SHIGUANG_SECRET`, and `SHIGUANG_DEV=1` (serve
`web/index.html` from disk instead of the embedded copy).

## Layout

```
cmd/study/            entry point and flags
internal/app/         Wails window, lifecycle, single-instance mutex
internal/config/      data directory, token, owner id
internal/server/      routes, bearer auth, token injection, error mapping
internal/store/       SQLite connection, DDL, migrations
internal/ops/         validation, transactions, state assembly
internal/secret/      .env parsing, AES-256-GCM, preview
internal/llm/         endpoint allowlist, no-redirect proxy, limits
web/index.html        byte-for-byte copy of src/app/index.html (hash-locked)
fixtures/             golden JSON generated by the frozen Python backend
build/windows/        manifest and version resources
```

## Security invariants

- Provider API keys exist only as ciphertext in SQLite. They never appear in
  the page, backups, logs, or error messages.
- `/api/chat` always uses the stored key and ignores any key in the request
  body.
- Only official Qwen/DeepSeek HTTPS endpoints are accepted, redirects are not
  followed, and only a whitelist of request fields is forwarded.
- The service binds `127.0.0.1` only. There is no account system and it must
  not be exposed to a network.
- Every request must address the loopback interface; a non-loopback `Host`
  (for example a DNS-rebinding attack) is rejected with `403` before any token
  is exposed.
- Request bodies are capped, the server sets read/write/idle timeouts, JSON
  responses send `Cache-Control: no-store`, and the token-bearing page sends
  `no-cache` with an `ETag`.
- A named mutex allows one instance per user session.

## Asset hash lock

`web/index.html` must not be edited here. Any functional change belongs in the
source page and must update `indexSHA256` in `web/embed_test.go` deliberately;
`go test ./web/` fails otherwise.

Intentional backend differences from the Python release are listed in
[`docs/parity.md`](docs/parity.md).
